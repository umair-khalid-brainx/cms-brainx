# Multi-Tenant CMS — project guide

**Read this first, then `docs/WORKLOG.md` for current state, `tickets/STATUS.md` for ticket status and
`docs/BACKLOG.md` for open items.**
Keep this file short. Depth belongs in `docs/`.

## What this is

A multi-tenant CMS proof of concept: one platform hosting many client sites, each on its own
host with its own branding and content. Built as a client-facing demo for an agency pitch and
as an engineering training project — **the architecture decisions are the assessed deliverable,
not code volume.**

`admin` is used directly by **client companies themselves** — a client's own staff log in and
build/manage their own site — not by us on their behalf. `web` is what that client's own
customers see. A platform-operator ("super-admin") panel for us to create/manage tenants is
deliberately deferred, not decided. See `docs/DECISIONS.md` D-014.

Three **independent** projects sharing one git repository (`CMS/` root, see `docs/DECISIONS.md`
D-012). No shared build, no workspace, no cross-imports except one published package. Each keeps
its own `package.json`/`node_modules`/`.gitignore`. They communicate over REST only.

| Folder   | Owns                                             | Dev port |
| -------- | ------------------------------------------------ | -------- |
| `api/`   | NestJS + Prisma. The only thing touching Postgres | 4001     |
| `web/`   | Next.js App Router. All public tenant sites (SSR + ISR) | 3000 |
| `admin/` | React SPA (Vite). Admin panel and block editor    | 5173     |

Production: one EC2 box behind nginx. `*.<domain>` → web, `admin.<domain>` → admin static build,
`api.<domain>` → api.

## Hard invariants — do not violate

1. **Tenant scoping is structural, not remembered.** Every content read/write goes through the
   repository layer, and every content method takes `siteId` as a required parameter. Nothing
   outside a repository imports `PrismaService`. An unscoped method must not exist to be called.
2. **Blocks are colour-agnostic.** A block component may reference `--site-*` CSS custom
   properties and nothing else — no hex values, no Tailwind palette classes. Verify with:
   `grep -rnE '#[0-9a-fA-F]{3,8}\b' src/blocks src/theme` → must return nothing.
3. **One block implementation, two surfaces.** Block components live in the shared `cms-blocks`
   package and are rendered by both the public site and the editor canvas. Never copy a block
   component into a second repo — see `docs/DECISIONS.md` D-008.
4. **The block registry is exhaustive by type.** `Registry = { [T in BlockType]: BlockDefinition<T> }`,
   so a block type without a component (or the reverse) is a compile error, not a blank section.
5. **Sanitise on write, never on read.** Stored HTML is already safe. Public rendering does not
   sanitise.
6. **ISR cache keys include the host.** A cache key on path alone serves tenant A's page to
   tenant B. Test with two hosts, never one.
7. **`content.blocks` JSONB is a contract.** Its shape is `cms-blocks/types.ts`. Changing a block's
   props is a data-format change — check what already-stored pages will do.
8. **Fixed palettes are deliberate.** 6 custom-field kinds; blocks are code-defined, not
   user-definable. A seventh field kind or a runtime block builder is a scope change, re-estimated
   rather than absorbed (`docs/EXECUTION_PLAN.md`, out-of-scope list).
9. **`path` on `content` is denormalised.** A slug change recomputes `path` for every descendant in
   one transaction, and only within that subtree.

## Gotchas — this machine and this stack

- **Port 4000 is taken by Local (the WordPress tool).** The API's canonical port is 4000 but
  `api/.env` overrides it to **4001** via `API_PORT`. `web` and `admin` env files point at 4001.
- **Docker is not installed.** Local Postgres is the Homebrew server on `:5432`, database `cms`,
  connected as the OS user. `api/docker-compose.yml` exists as an alternative and maps host port
  **5433** so it can never clash.
- **Prisma 7 has no bundled engine.** `PrismaService` must pass a driver adapter (`PrismaPg` built
  from `DATABASE_URL`). Config lives in `api/prisma7.config.ts`, which loads `.env` via `dotenv` —
  Prisma does **not** read `.env` by itself.
- **The Prisma client is generated TypeScript** into `api/src/generated/prisma`, gitignored and
  regenerated by `postinstall`. A fresh clone needs `npm install` before it typechecks.
- **A fresh clone must build `cms-blocks` once** (`cd cms-blocks && npm install && npm run build`).
  `web` and `admin` import it from its gitignored `dist/`; without that, both fail with "Module not
  found: Can't resolve 'cms-blocks'" even though `node_modules/cms-blocks` exists. Restart their dev
  servers after building.
- **Public sites live on subdomains: `http://corrick.lvh.me:3000`**, not `127.0.0.1:3000`. `lvh.me`
  is a public DNS wildcard that resolves to `127.0.0.1`, so it needs a network connection. Any host
  that isn't `<subdomain>.lvh.me` gets the "no site at this address" 404 (D-030).
- **Public pages are cached (ISR), but only in a production build** (D-039). `next dev` renders every
  request fresh, so caching and on-demand refresh can only be tested with `next build && next start`.
  Look for the `x-nextjs-cache: HIT|MISS` header. `api` needs `WEB_REVALIDATE_URL` and
  `REVALIDATE_SECRET`, and `web` needs the same `REVALIDATE_SECRET`. Without them, edits show up
  only after the 60 s timer.
- **`/__revalidate` is reserved on every host** (D-039), the same way as `/__preview`.
- **`/__preview/<token>` is reserved on every tenant host** (D-037). `web/src/proxy.ts` sends it to an
  uncached preview route instead of `/sites/...`. No slug can start with `_`, so it can't clash
  with a page. Keep it that way if slug rules change.
- **Claude's built-in browser pane blocks `*.lvh.me` sub-requests** (CSS/JS fail with
  `ERR_BLOCKED_BY_CLIENT`), so public pages look unstyled there. The server is fine; check with
  `curl` or a headless Chrome screenshot instead.
- **`@nestjs/config` is version 12.x for Nest 12**, not 4.x — the packages were realigned.
- **`localhost:3000` may redirect to `/en` and 404.** A stale cached 308 from an unrelated project
  on that origin. Use `http://127.0.0.1:3000` (different origin) or clear site data. Not a bug in
  this project.
- **`turbopack.root` must include `cms-blocks`, not just `web`.** It's set to `path.resolve("..")`
  (the `CMS/` container), not `path.resolve(".")` — `cms-blocks` is a sibling package outside `web/`,
  and Turbopack's production build refuses to resolve a symlinked module whose real path is outside
  the configured root, even though `next dev` tolerates it. Silent-looking "Module not found" for a
  package that clearly exists in `node_modules` is the symptom.
- **Tailwind's `@source` path for `cms-blocks/src` depends on the importing file's folder depth —
  do not copy the path between repos.** `web/src/app/globals.css` is 3 levels deep, so it's
  `../../node_modules/cms-blocks/src`; `admin/src/index.css` is only 2 levels deep, so it's
  `../node_modules/cms-blocks/src`. Getting this wrong doesn't error — Tailwind just silently
  compiles almost nothing (check for `--tw-rotate-x` and a handful of generic utilities and little
  else if this is wrong; a real build has hundreds of classes).
- **`web/.gitignore` ignores `.env*`**, so `!.env.example` is required to keep the example tracked.
- **Headless Chrome `--window-size` does not reliably set layout width.** To check responsive
  behaviour, render the page in a fixed-width `<iframe>` inside a probe page and screenshot that.
- **Tailwind 4 skips `node_modules`.** Both repos must declare `@source "../../node_modules/cms-blocks/src";`
  or the shared block components ship with no CSS.
- **Blocks need a `SiteThemeRoot` ancestor or every `--site-*` var is undefined.** `web` gets this
  from `SiteChrome.tsx`; `admin`'s Puck canvas gets it via `config.root.render` in `EditorPage.tsx`.
  Structural CSS (grid, spacing, borders) still renders fine without it — only colour, radius and
  type silently fall back to browser defaults, which can look plausible by accident. Confirm with a
  theme whose colours are obviously distinct from any fixture's, not just "does it look styled."
- **`admin` has no `next/font`.** `theme.ts`'s type sets reference `--font-fraunces`, `--font-karla`,
  etc. — `web` gets those for free from `next/font` in `layout.tsx`; `admin` loads the same families
  as plain Google Fonts in `index.html` and maps them to the same variable names in `index.css`.
- **Puck mounts each field's `render` function twice** — a real, visible instance in the sidebar, and
  a second, zero-size, invisible instance elsewhere in the DOM (inside its own `_FieldsPlugin`
  wrapper). Both are wired to the same underlying value, so this is invisible to a real user, but a
  CDP/test script using `document.querySelector`/`querySelectorAll` against a custom field's class
  name will match both — filter to `getBoundingClientRect().width > 0` to get the one a person could
  actually click. Found verifying `ImageUploadField`'s "Browse" button (D-027).
- **Puck's drag-and-drop only responds to trusted, stepped mouse input.** JS-dispatched
  `PointerEvent`s and the built-in browser pane's one-jump drag both do nothing. Real Chrome driven
  over the DevTools protocol (`Input.dispatchMouseEvent`: press, ~40 small `mouseMoved` steps with
  `buttons: 1`, release) works, including drags inside the scaled canvas iframe — map iframe rects
  through `iframeRect.width / iframe.clientWidth`. The action bar's `Duplicate`/`Delete` buttons are
  inside the iframe, found by `aria-label`.
- **`@puckeditor/core@0.23.0`'s own Publish button does render** (D-019's original "it doesn't" was
  wrong — corrected in D-028) as a `<span>`, not a `<button>`, inside its header's `_PuckHeader-tools`.
  `EditorPage.tsx` keeps its own `.editor-publish` button as the one source of truth and suppresses
  Puck's via `overrides={{ headerActions: () => <></> }}` — without that override, both render and a
  user sees two working Publish buttons stacked on top of each other.

- **Contact forms need `FORM_SUBMIT_SECRET` set to the same value in `api/.env` and
  `web/.env.local`.** Missing or mismatched, every submission fails with a generic "could not be
  sent" (web logs why; the API returns 503 or 403). Restart both after changing it (D-034).
- **The contact form rate limit trusts the last `X-Forwarded-For` entry.** `next dev` passes a
  client-sent one straight through, so locally it can be faked. Production nginx must overwrite it
  with `$remote_addr` (`DEP-01a`).

- **Puck's field panel is a single `<form>`.** A custom field that renders its own `<form>` nests
  it, and pressing Enter or a submit button submits the outer one: the editor reloads (the URL gains a
  trailing `?`). Use a `div`, `type="button"` and handle Enter yourself (`RichTextToolbar.tsx`, D-045).
- **Puck's `richtext` value is a string in storage but a rendered node inside the canvas.** The
  `RichText` block accepts both. Inside the canvas Puck also wraps the content in extra elements, so
  style it with descendant selectors, not `>`; and Puck's own stylesheet can beat a plain utility (the
  quote's left rule needed `!`).
- **After editing a file under `cms-blocks/src`, admin's dev server may not regenerate Tailwind
  classes** (it doesn't rescan `node_modules`). Rebuild `cms-blocks`, then `touch admin/src/index.css`
  and reload; if classes are still missing, restart the dev server.
- **Dev servers for a worktree:** run them with `npm --prefix <app> run dev`. `npx --prefix admin vite`
  runs from the repo root and serves a blank page.

- **`API_PUBLIC_URL` must be set to the API's public address in production** (D-050). `api` builds the full
  address of every picture and file on an entry page and in a listing from it, and falls back to
  `http://localhost:4001`; unset, every entry image points at localhost. (`DEP-01b`'s checklist.)

## Working style — preferences

- **Teach properly when I'm learning something new.** First principles, concrete examples, real
  code. Compressed bullet fragments do not land; if an explanation is too terse I will say so.
- **On decisions: lay out the real options with their costs, give a recommendation, then let me
  decide.** Do not settle architecture unilaterally. Record the outcome in `docs/DECISIONS.md`.
- **Verify before asserting.** Run it, curl it, screenshot it. Do not describe behaviour you have
  not observed.
- **Subagents are allowed without asking** — use them when they help, and always run the
  reviewer and verifier for a ticket before marking it DONE. Multi-agent workflows still need my
  ask first.
- Say plainly what is done, what is not, and what was skipped.
- Do not throw too much information at one time. comunicate with me like a friend and ask me back and forth questions and explain me concepts in a interactive conversations. dont just throw all the information at once

## Doc maintenance rules

- Non-obvious or architectural choice → **append** a dated entry to `docs/DECISIONS.md`.
  Append only; a reversal is a new entry that says which one it supersedes.
- Finished a task or meaningful chunk → dated entry at the top of `docs/WORKLOG.md`.
- Ad-hoc ask, feedback, or off-flow request → log in `docs/BACKLOG.md`; mark done, dated, when shipped.
- Ticket status changed → update `tickets/STATUS.md` and that ticket's `tickets/<ID>.md` (D-033).
  `docs/EXECUTION_PLAN.md` no longer holds status.
- Invariant or gotcha changed → update this file (and `docs/ARCHITECTURE.md` if structural).
- Absolute dates only (`2026-08-31`), never "today".
- If a doc contradicts the code, **the code wins** — fix the doc in the same pass.
