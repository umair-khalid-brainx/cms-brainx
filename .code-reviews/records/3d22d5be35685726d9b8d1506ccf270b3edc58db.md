## Summary

Admin editor restyle (single repo; only `admin/` and `docs/` touched, no API contract change). Stack: React (Vite)
in `admin/`; the repo root has no stack marker, so `admin/package.json` was used.

- **Block picker**: `puck/config.tsx` adds Puck `categories` (all 15 block types placed exactly once — checked
  against `cms-blocks/src/types.ts`). New `BlockDrawerItem.tsx` replaces Puck's drawer row with an inline-SVG icon
  tile via the `drawerItem` override; `EditorPage.css` lays the drawer out as a 3-column grid using Puck 0.23's
  `data-puck-drawer` / `data-puck-drawer-item` attributes (both confirmed present in the installed Puck build).
- **Editor chrome**: the top bar moves from a fixed dark bar to the admin's light/dark panel tokens, with a
  two-line heading, a status chip with a dot, and quieter secondary buttons. Puck is themed by overriding its
  semantic `--puck-color-*` tokens on `.editor-puck` (all names confirmed against Puck's stylesheet), with a full
  dark-mode remap. `ImageUploadField.css` switches to Puck tokens with admin fallbacks.
- **Root label**: `configFor` takes an optional label, so an entry's empty-selection panel says e.g. "Post".
  `useMemo` deps `[type, theme]` already cover `type?.singularName`.
- All `--ui-*` tokens referenced exist in `admin/src/index.css`.

Re-review (2026-10-15T09:36:03Z): all six earlier findings are fixed. The top bar now defines mode-aware
`--tb-*` tokens (light values by default, dark values under `prefers-color-scheme: dark`) and uses them for muted
text, hover surfaces, borders and the danger chip. The status live region stays in the page when empty. The dot no
longer shows for a notice on its own, and the icon map is typed by block name. A local typecheck was not run: this
worktree's `admin/` has no `node_modules`.

- **admin/src/pages/EditorPage.css:36** — In light mode, hovering the back link or a secondary/Share button makes it unreadable: dark text on a near-black background. *(correctness)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Hover surfaces now use `--tb-hover`, which is `--ui-surface` (#f3f5f7) in light mode and `--ui-panel-dark-2` only under `prefers-color-scheme: dark`. ### Medium (2)
- **admin/src/pages/EditorPage.css:23** — Light-mode text contrast in the top bar falls below WCAG AA. *(accessibility)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: `.editor-back` and `.editor-mode` now use `--tb-muted`, which is `--ui-text-3` (#5f6b7a, about 5.3:1 on white). `.editor-status` and `.editor-site` use `--tb-muted-2`, which is `--ui-text-2` (#46505c, about 8:1). The error chip uses `--tb-danger`, which is `--ui-danger` (#b42318, about 6:1 on its 14% tint). All three switch to the `-dark` tokens only inside the dark-scheme block.
- **admin/src/pages/EditorPage.css:84** — `.editor-status:empty { display: none }` hides the `role="status"` live region until the moment it gets content, so screen readers may not announce "Saved …" or a save error. *(accessibility)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: `:empty` now only sets `padding: 0; margin: 0`, so the element is never `display: none` and the live region stays in the accessibility tree. When there is no message, React renders no children (the `&&` gives `false` and the text gives `''`), so `:empty` still matches and the chip collapses visually.
